# PcRemoteBot

Учебный Telegram-бот на C# для удалённого управления моим компьютером с Windows: блокировка экрана и запуск программ командами из чата.

## Что умеет

- `/lock` блокирует экран Windows
- `/steam` запускает Steam
- `/chrome` запускает Chrome
- Любой другой текст бот повторяет эхом
- Бот отвечает только владельцу: все сообщения проверяются по Telegram ID. Чужим он один раз отправляет предупреждение, дальше молчит
- Все события записываются в консоль с временем

## Технологии

- C#, .NET 10, консольное приложение (top-level statements)
- Библиотека [Telegram.Bot](https://github.com/TelegramBots/Telegram.Bot) 22.x
- P/Invoke: вызов функции `LockWorkStation` из `user32.dll`
- `Process.Start` для запуска программ

## Как запустить

Нужен компьютер с Windows и .NET SDK.

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Узнайте свой числовой Telegram ID.
3. Задайте две переменные окружения:
   - `BOT_TOKEN`: токен бота
   - `ALLOWED_USER_ID`: ваш Telegram ID
4. Запустите проект.

В Visual Studio переменные можно задать в файле `Properties/launchSettings.json`. В репозиторий он не включён, потому что содержит секреты. Структура такая:

```json
{
  "profiles": {
    "PcRemoteBot": {
      "commandName": "Project",
      "environmentVariables": {
        "BOT_TOKEN": "ваш_токен",
        "ALLOWED_USER_ID": "ваш_id"
      }
    }
  }
}
```

## Безопасность

- Токен и ID не хранятся в коде и не попадают в репозиторий
- Бот выполняет только заранее прописанные в коде команды, текст из сообщений в запуск программ не передаётся
- Работает только пока запущена программа на ПК

## Чему научился

- Как работает `async/await`: пока метод ждёт ответа (например, от Telegram), он приостанавливается и освобождает поток, а затем продолжается с того же места. `Task` это «чек» на результат операции, а не сам результат
- Как бот получает сообщения: Telegram не может сам обратиться к домашнему ПК, поэтому бот сам опрашивает сервер (long polling), а обработка идёт через события (`OnMessage`)
- Как C# вызывает функции Windows (P/Invoke, `user32.dll`) и как запускать программы через `Process.Start` и `UseShellExecute`
- Как не хранить секреты в коде: переменные окружения, `.gitignore`, проверка перед отправкой в репозиторий
- Как защитить бота: проверка отправителя по ID, ранний выход через `return`, безопасная работа с `null` (`?.`)
- Зачем нужен `lock`: сообщения обрабатываются на разных потоках, и общую коллекцию (`HashSet`) нельзя менять одновременно
